# Attention Lab

A hands-on, beginner-friendly tutorial that builds up to a **real trainable decoder-only transformer**, running entirely in the browser. No API keys, AI services, machine-learning dependencies, build step, or GPU are required.

## Run it

Serve the `dist` directory with any static web server. For example, from this repository:

```sh
python3 -m http.server 8000 --directory dist
```

Then open `http://localhost:8000`. Use HTTP(S), rather than double-clicking the HTML file: ES modules and module workers need a web origin. The complete app is in `dist/`; it can also be deployed to GitHub Pages, Netlify, Vercel, Hostinger, or another static host. No rewrite rules are needed: lessons use URL hashes. Serve `.js` files with a JavaScript MIME type and the checkpoint as JSON.

## What's interactive

13 lessons cover the next-token task; editable datasets and holdout splits; character, word, and pair-merge tokenization; shifted training windows; actual learned embeddings and positions; draggable query/key vectors and editable values; a complete live transformer trace; logits, probabilities and loss; gradient descent; real training; real attention heatmaps; autoregressive generation; checkpoint export/import; and the path from a tiny model to larger assistants.

Each lesson has a plain-language explanation, an experiment, a short knowledge check, and expandable technical details. Illustrative sandboxes are explicitly distinguished from actual model measurements. The layout supports mobile screens, keyboard controls, and reduced motion. Drag controls have range-input alternatives.

## The actual model

- Unicode character tokenizer, up to 160 distinct characters.
- Learned token and absolute position embeddings.
- One pre-LayerNorm decoder block, with 1, 2, or 4 causal attention heads.
- Width 16, 24, or 32; context 8, 16, 24, or 32 characters.
- Feed-forward expansion to 4× width with tanh-approximated GELU.
- Residual additions, final LayerNorm, and untied vocabulary projection.
- All embeddings, projections, biases, normalization scale/offsets are trainable.
- Handwritten matrix-level reverse-mode autodiff in `dist/engine.js`.
- Stable softmax / cross-entropy, Adam with bias correction, global gradient norm clipping at 1.
- Four windows per optimizer step, sequentially accumulated and averaged.
- Seeded initialization, training, and independent sampling RNG.
- CPU Float64 typed arrays; a module Web Worker keeps computation off the UI thread.
- No dropout, weight decay, scheduler, KV cache, pretrained API, or simulated loss curves.

The exact count is computed from arrays. For vocabulary V, context T, and width D it is `12D² + (T + 15)D + 2VD + V`.

The default Frost corpus, width 24/context 24/two heads, has 9,808 parameters (40 vocabulary characters). A single poem teaches optimization and memorization, not broad language competence. On slower devices, use width 16 and context 8 or 16. Pause is processed between chunks of at most ten updates; timing depends on hardware.

## Data and evaluation

The corpus is split contiguously (default 85%/15%) **before** overlapping windows are extracted. No training window or target crosses into the held-out segment. The vocabulary is built from all selected characters, including held-out characters; the held-out targets are never optimized.

Every ten updates, evaluation averages twelve fixed sampled windows per split, with deterministic sampling independent of the training RNG. The chart distinguishes training-text evaluation loss from held-out loss. It is a tiny within-document holdout, not a robust external benchmark. Repeating-pattern data deliberately repeats across the split; success there demonstrates learning the pattern, not broad generalization. The baseline is uniform next-character loss `ln(V)`.

`dist/poem-checkpoint.json` is generated by the included engine and can be loaded from the training room. It was trained for 1,200 steps on the training split. Training loss falls from 3.750 to 0.474 nats, while held-out loss is 3.701 nats: it deliberately illustrates overfitting. Recreate it with `node scripts/train-example.mjs`. It is not a shortcut used by the initial model. The page initially creates fresh random weights.

## Persistence and privacy

Text, model weights, and training remain in the browser. Refreshing starts over; download a JSON checkpoint to preserve work. Checkpoints contain the corpus, configuration, weights, Adam moments, training RNG, and loss history. Import validates dimensions, finite values, and size. Training text is included in exports, so share them accordingly. There is no analytics, remote inference, user account, or runtime CDN dependency.

Optional WebMCP support exposes read-only tutorial state and lesson navigation when the browser supports `document.modelContext`. The app is fully usable without it.

## Verify

Node.js 20 or newer, with no package installation:

```sh
npm test
npm run check
```

Tests check representative parameters in **every parameter family** by finite differences, exact causal masking, loss improvement, training/validation boundaries, genuine parameter updates, checkpoint/Adam continuation, stable probabilities, invalid input rejection, inference immutability, and worker cancellation behavior.
